# Retail360 — LinkedIn & GitHub Descriptions

## GitHub short description

End-to-end retail analytics platform using PostgreSQL, Power BI, DAX, PBIP/TMDL, Python, Docker and GitHub Actions — dimensional warehouse, 78 governed KPIs, 10-page report, RLS and runtime reconciliation.

## LinkedIn project description

Built **Retail360**, an end-to-end retail analytics platform using Microsoft AdventureWorksDW data.

The project covers the complete analytics engineering workflow:

- PostgreSQL raw → staging → analytics warehouse
- harmonized Internet + Reseller sales fact
- inventory snapshot modelling
- star-schema Power BI semantic model
- 78 governed DAX measures
- YoY/MTD/QTD/YTD and role-playing date analysis
- customer, product, channel, promotion, territory and inventory analytics
- territory-based RLS demonstration roles
- PBIP/TMDL/PBIR source control
- automated SQL, Python, DAX and GitHub Actions QA
- live Power BI runtime reconciliation: 34/34 exact KPI checks + 78/78 measure smoke checks

Key verified metrics include 121,253 sales lines, 31,455 orders, 274,776 units and 109.81M consolidated sales.

Repository: https://github.com/rjraunak04/retail360-powerbi-analytics

## LinkedIn post draft

I recently completed **Retail360 — Enterprise Retail Analytics**, an end-to-end Power BI and analytics engineering project.

Instead of starting from visuals, I built the full pipeline:

**AdventureWorksDW → PostgreSQL → staging → star schema → Power Query → Power BI semantic model → DAX → report → RLS → automated QA**

Highlights:

- 922K+ source rows across 14 source files
- unified Internet + Reseller sales model
- 121K+ sales lines and 776K+ inventory snapshots
- 78 governed DAX measures
- 10 analytical report pages + report-page tooltip
- role-playing Order / Due / Ship date analysis
- latest-snapshot inventory analytics
- territory RLS
- PBIP/TMDL/PBIR source control
- Docker + GitHub Actions
- 34/34 live KPI reconciliation checks
- 78/78 DAX measure smoke checks

One of the biggest lessons was that a strong BI project is not just a dashboard. The data grain, semantic model, KPI definitions, edge cases, security and validation are what make the report trustworthy.

Tech: **PostgreSQL | SQL | Power BI | DAX | Power Query | Python | Docker | Git | GitHub Actions**
